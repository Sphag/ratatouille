# Архитектура и разработка

T04 завершена 8 октября 2026 года. Владелец поручил продолжить разработку и делегировал технические решения помощнику. Здесь зафиксирован выбранный стек; продуктовые требования остаются в [PROJECT_BRIEF.md](PROJECT_BRIEF.md).

## Стек

| Компонент | Выбор | Назначение |
|---|---|---|
| Python | 3.13.16 | Сервер и будущий процесс бота; версия в `.python-version` |
| Зависимости Python | uv 0.12.23, `uv.lock` | Управляемый Python и окружение `.venv` |
| HTTP | FastAPI 0.142.4, Uvicorn 0.54.0 | API и выдача собранного клиента |
| Telegram | aiogram 3.31.0 | Открытие Mini App и сообщения в следующих задачах |
| Хранение | SQLite, SQLAlchemy 2.0.54, Alembic 1.20.0 | Модель и миграции будут добавлены в T05 |
| Клиент | React 19.3.0, TypeScript 6.0, Vite 8.3.3 | Mini App; точные версии в `frontend/package-lock.json` |
| Node.js | 24.21.0 LTS, npm 11.19.0 | Установка и сборка клиента; используется установка T02 |
| Проверки Python | Ruff, mypy, pytest, httpx2 | Форматирование, линтер, строгая типизация и HTTP-тесты |
| Проверки клиента | TypeScript, ESLint, Prettier | Типы, правила React и форматирование |

Точные версии Python-пакетов фиксирует `uv.lock`, npm-пакетов — отдельный lockfile клиента. Диапазоны в манифестах задают границы будущего обновления; обычная установка использует только lockfile. TypeScript ограничен веткой 6.0 для совместимости с выбранным typescript-eslint. TestClient использует поддерживаемый [Starlette клиент httpx2](https://www.starlette.io/testclient/).

FastAPI выбран для типизированных HTTP-границ и тестирования. React и TypeScript дают единый клиент для форм рецептов, меню и чек-листов. SQLAlchemy и Alembic подготовлены для явной модели и воспроизводимых миграций SQLite. Подключений к базе, схемы и миграций в T04 ещё нет.

## Границы и структура

| Путь | Ответственность |
|---|---|
| `src/ratatouille/` | Python-пакет приложения; сейчас ASGI-приложение в `app.py` |
| `tests/` | Проверки поведения сервера |
| `frontend/src/` | Русский интерфейс Mini App; сейчас стартовый экран |
| `assets/` | Общие изображения сервиса |
| `tools/dev/` | Установка uv и команды настройки и проверки приложения |
| `tools/mcp/` | Независимые инструменты помощника, собственный npm-lockfile |
| `tools/publication/` | Проверка явного списка публичных файлов и подготовка Issues |
| `docs/` | Обезличенные требования и документация разработки |

HTTP-процесс принимает запросы по `/api/` и выдаёт сборку клиента по `/` и `/assets/`. Сейчас доступен только `GET /api/health` с ответом `{"status":"ok"}`: это проверка работающего процесса. Без сборки клиентской части `/` возвращает 503 с понятным сообщением; неизвестные API возвращают 404.

В T05 расчёты и правила меню будут отдельными Python-модулями без зависимости от HTTP или Telegram. Слой хранения будет отвечать за транзакции и снимки подтверждённых планов. API и схема выбираются в T05 по требованиям. В T11 появятся проверка Telegram `initData` перед доступом к пользовательским данным и отдельный процесс aiogram. В T12 напоминания будут исполняться асинхронным процессом бота, с расписанием в SQLite и часовым поясом Europe/Moscow; дополнительный брокер и планировщик сейчас не нужны. Правила повторных отправок остаются в T12.

## Запуск

Основная проверяемая среда — Linux x86_64 в WSL. Команды из [README](../README.md) выполняются из корня проекта. Установщик скачивает uv фиксированной версии и проверяет SHA256 архива. uv, его кэш и управляемый Python сохраняются в исключённом `tools/dev/.cache/`; глобальные Python и настройки оболочки не меняются. Node.js требуется версии 24; при отсутствии используется согласованный установщик T02.

Разработка: Uvicorn слушает `127.0.0.1:8000`, Vite — `127.0.0.1:5173` и проксирует `/api/` на сервер. Vite разрешает файловый доступ только к клиенту и общим изображениям. После сборки сервер сам выдаёт клиент. Каталог сборки выбирается переменной `RATATOUILLE_FRONTEND_DIR`, по умолчанию `frontend/dist`. Сборку нужно создать до старта сервера; после пересборки с изменением каталога ресурсов сервер перезапускается.

Для Windows предпочтителен тот же запуск в WSL. Нативный Windows в T04 не проверялся: там потребуются uv 0.12.23, Python 3.13.16 и Node.js 24, установка `uv sync --locked` и `npm --prefix frontend ci`, затем аналогичные команды `uv run` вместо Bash-обёртки. Bash-установщик uv предназначен только для Linux x86_64.

Схема Docker согласована для T14: многоэтапная сборка клиента, Python-образ с готовой сборкой, отдельные процессы web и bot из общего образа; SQLite хранится в постоянном томе. Для Windows Docker запускается через Docker Desktop с WSL, для VPS — через Docker Engine. Контейнеры, Compose, HTTPS и CI будут реализованы в T14. Docker в текущей среде отсутствует, контейнерный запуск не проверялся.

## Конфигурация и проверки

`.env.example` содержит пустой `BOT_TOKEN` и пример пути к сборке. В T04 токен не используется и не требуется; бот не запускается. Переменные передаются процессу через окружение, `.env` автоматически не читается. Секреты, локальные базы, `.venv`, `node_modules`, сборки, отчёты и скриншоты исключены из Git. Личные анкеты не нужны для установки и проверки.

`bash tools/dev/check.sh` проверяет Python, запускает HTTP-тесты и тесты публикации, затем проверяет и собирает клиент. Тесты сервера охватывают работу без токена и сборки, корректную выдачу ресурсов, 503, 404 и невозможность выхода из каталога ресурсов. Бизнес-сценарии меню будут проверяться после их реализации. В управляемой песочнице TestClient и браузеру может требоваться разрешение на локальные сокеты; в обычном WSL-терминале специальная настройка не нужна.
