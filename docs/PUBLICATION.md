# Публикация T03

Владелец отдельно согласовал публичный репозиторий `Sphag/ratatouille`, лицензию MIT и продолжение T03. Публикуется точный список из [PUBLICATION_MANIFEST.md](PUBLICATION_MANIFEST.md); задачи T00–T15 переносятся в Issues. T00–T02 завершены и должны быть закрыты, T03 остаётся открытой до проверки удалённого результата и привязки текущей папки. Начало T04–T15 требует отдельного согласования.

## Подготовка снимка

Нужны Python 3.8 или новее и Git. Из корня проекта:

```bash
python3 tools/publication/prepare.py
```

Для этих служебных скриптов выбран стандартный `unittest`, без внешних библиотек. Это не выбирает тестовый фреймворк будущего приложения. Проверка:

```bash
python3 -B -m unittest discover -s tools/publication -p 'test_*.py' -v
```

Скрипт не использует сеть и не меняет корневую `.git/`. Он читает только публичные файлы из перечня, проверяет локальные ссылки и характерные маркеры секретов, исключения Git и точное соответствие индекса перечню. Неизвестные файлы, личные анкеты и содержимое служебных каталогов не копируются. Проверка маркеров не заменяет просмотр содержания перед публикацией.

В новом исключённом каталоге `tools/publication/.cache/run-…/` сохраняются:

- `repository/`: отдельный Git-репозиторий, ветка `main`, один коммит с публичными материалами, настроенный `origin`;
- `ratatouille.bundle`: переносимая копия этого коммита;
- `issues.json` и `issues/T00.md`–`issues/T15.md`: заголовки, тексты, зависимости и предполагаемые состояния Issues;
- `report.json`: результаты проверок, SHA256 каждого файла и SHA коммита; `published: false` означает, что скрипт не публиковал снимок.

Повторный запуск создаёт новый снимок и сохраняет предыдущий. После изменения публичных документов нужно снова запустить подготовку. Настройки Git задаются только для дочерних команд, глобальная конфигурация не меняется; автор — `Sphag`, адрес коммита — GitHub noreply.

## Создание репозитория и публикация

7 октября 2026 года владелец создал [Sphag/ratatouille](https://github.com/Sphag/ratatouille). Через подключённый GitHub подтверждены владелец `Sphag`, публичная видимость и пустые списки веток и Issues. Попытки создать `LICENSE` и Issue T00 отклонены: `403 Resource not accessible by integration`; удалённых изменений нет. Списки установок и подключённых аккаунтов интеграции вернули пустой результат. Метаданные с правами владельца `push/admin` не подтверждают права интеграции. Запрос `gh` с расширением сетевого доступа не завершился за 20 секунд; недействительность его токена не установлена.

Владелец уточнил, что использует отдельный GitHub MCP с fine-grained PAT, а затем сообщил об обновлении прав: `Sphag/ratatouille`, `Contents: Read and write`, `Issues: Read and write`. Этот MCP и встроенный коннектор — разные подключения. Повторная запись через встроенный коннектор всё ещё вернула 403; этот результат не проверяет PAT. В текущей управляемой сессии прямые инструменты отдельного GitHub MCP недоступны и `GITHUB_MCP_TOKEN` не задан в окружении.

Для продолжения через согласованный MCP открыть обычный терминал WSL в корне проекта и выполнить:

```bash
read -rsp 'GitHub MCP token: ' GITHUB_MCP_TOKEN
export GITHUB_MCP_TOKEN
codex
```

После команды `read` вставить токен и нажать Enter; значение не отображается и не записывается в историю. Токен не присылать в чат. В локальном клиенте проверить GitHub через `/mcp`, затем поручить: «Продолжи согласованную T03: публикация Sphag/ratatouille под MIT и перенос T00–T15 в Issues. Используй проектный GitHub MCP с PAT. Сначала проверь доступ». Проектная конфигурация уже содержит `bearer_token_env_var = "GITHUB_MCP_TOKEN"`; служебные настройки из текущей сессии не меняются.

Повторно создавать репозиторий и согласовывать T03 не нужно. После появления доступа проверить текущее удалённое состояние, заново собрать снимок и продолжить публикацию. Если появился новый начальный коммит, сначала сверить его содержимое; не перезаписывать чужие изменения.

Альтернатива из обычного локального терминала с работающим GitHub CLI: после подготовки перейти в каталог `repository/` из вывода скрипта и выполнить из него:

```bash
gh api user --jq .login
git ls-remote origin
git push -u origin main
```

Первая команда должна вернуть `Sphag`; при другом аккаунте остановиться. Вторая команда должна успешно вернуть пустой список ссылок, пока репозиторий пустой. При наличии веток сначала сверить их содержимое со снимком. Не использовать принудительную отправку. Тексты Issues готовы для переноса; после создания заменить ссылки зависимостей на фактические номера Issues, закрыть T00–T02 и записать номера в бэклог.

## Привязка текущей папки

В управляемой сессии корневая `.git/` доступна только для чтения. Следующие команды выполняются владельцем из обычного локального терминала **после публикации и проверки `main`** в корне исходного проекта. Они предназначены для текущего состояния, когда Git-репозитория здесь ещё нет:

```bash
git init
git symbolic-ref HEAD refs/heads/main
git remote add origin https://github.com/Sphag/ratatouille.git
git fetch origin main
git reset --mixed origin/main
git branch --set-upstream-to=origin/main main
git status --short
git ls-files
git check-ignore docs/QUESTIONNAIRE.md docs/FOLLOW_UP.md .agents/test .codex/test .aws/test
```

`reset --mixed` устанавливает указатель ветки и индекс из опубликованного коммита, сохраняя все файлы рабочей папки. Локальные отличия останутся видимыми в `git status`. Если репозиторий уже инициализирован, эти команды не повторять вслепую: сначала проверить текущую ветку и `origin`. Личные анкеты и локальные настройки должны остаться исключёнными.

Эти проверки не подтверждают удалённую публикацию.

T03 закрывается после проверки публичной видимости, MIT, точного дерева файлов, изображений и шаблонов задач на GitHub; наличия всех 16 Issues с зависимостями и корректными статусами; успешной привязки исходной папки.
