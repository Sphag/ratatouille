# T06 — библиотека и управление рецептами

Статус: реализация подготовлена; подтверждение стартовых карточек владельцем ещё требуется. Дата: 8 октября 2026 года.

Владелец поручил проверить и слить T05, затем выполнить T06; PR #18 слит, Issue #6 закрыта. Извлечение рецептов из указанного внешнего отчёта разрешено отдельно. Исходный отчёт и личные анкеты не копируются в проект.

## Стартовые данные

[data/starter_recipes.json](../data/starter_recipes.json) содержит только идентификатор набора, статус согласования, названия, инструкции, выход рецепта, ручные КБЖУ и количественные ингредиенты 18 карточек. [Карточки для проверки](T06_STARTER_REVIEW.md) содержат все переносимые поля и отмеченные пробелы источника. Цены, клинические выводы, личные данные, недельное меню и показатели клетчатки не импортируются.

Каждый рецепт исходника описан на одну порцию. КБЖУ перенесены без пересчёта; половина яйца — 0,5 шт. Вода и специи без количества остаются вне списка покупок. Альтернативы продукта не выбираются за пользователя; неполные инструкции не дополняются догадками. Масса готового блюда и ориентир контейнера не присваиваются карточкам.

Импорт требует согласованного набора и отдельного подтверждения пользователем просмотренных карточек. Запрос передаёт отпечаток просмотренного состава; изменение состава требует нового просмотра. Все 18 рецептов, ингредиенты и запись о завершении импорта сохраняются в одной транзакции. Повторный или конкурентный запрос не создаёт дубликаты и не перезаписывает изменённые либо архивные карточки. Импорт каждому пользователю создаёт собственные рецепты; допуск всех новых карточек по умолчанию выключен.

Миграция `0002` добавляет только таблицу `starter_imports` с уникальной парой владельца и набора. Она не меняет рецепты или подтверждённые меню T05.

## Формы и сервисы

Клиент показывает библиотеку, архив и стартовые карточки. Через поля можно задать название, инструкцию, положительный целочисленный выход, ручные КБЖУ на порцию и количественные ингредиенты с единицами г/кг/мл/л/шт. В форме есть добавление и удаление строк ингредиентов, сохранение и отмена, отдельный явный допуск к подбору. При редактировании допуск нужно подтвердить заново после изменений.

Архивирование требует подтверждения и скрывает рецепт из библиотеки и подбора. Восстановление возвращает прежнюю карточку; физическое удаление не добавлено. Старые версии и подтверждённые планы сохраняются.

`Catalog` использует транзакции `Store` и проверяет владельца. Редактирование сравнивает текущую версию и исходные флаги допуска/архива; устаревшее сохранение возвращает конфликт и не меняет данные. Точные совпадения имён продуктов используют существующую идентичность ингредиента владельца; похожие названия и варианты не объединяются автоматически. Явный чужой идентификатор ингредиента отклоняется.

HTTP-граница принимает числа строками с десятичной точкой, без `float`, NaN, Infinity или экспоненты. Форма допускает запятую и преобразует её в точку. Пределы ввода — до 30 цифр целой части и 20 дробной, имя до 200 символов, инструкция до 10000, до 200 строк продуктов, выход до 10000 порций. Это границы формы, а не автоматическое масштабирование порций. Ответы сохраняют все цифры, включая малые дробные значения и ранее сохранённые данные T05 с большей точностью.

## Локальный запуск до T11

Проверка Telegram `initData` остаётся в T11. Основной `ratatouille.app:app` не подключает личные HTTP-маршруты. Для проверки T06 есть отдельный явный процесс:

```bash
bash tools/dev/uv.sh run --locked python -m ratatouille.local_app --init
npm --prefix frontend run build
bash tools/dev/uv.sh run --locked python -m ratatouille.local_app
```

Команда `--init` применяет миграции и создаёт локальный профиль. Повторный запуск сохраняет тот же профиль; данные находятся в БД `RATATOUILLE_DB_PATH`, идентификатор профиля — в соседнем исключённом `*.local-owner.json`. Обычный запуск не создаёт профиль или БД; отсутствующие данные требуют явного `--init`.

Сервер слушает только `127.0.0.1:8000`, не доверяет proxy-заголовкам, проверяет loopback-адрес клиента, Host и Origin. Изменения требуют специального заголовка приложения; CORS не открывается. Ответы с данными используют `Cache-Control: no-store`. Идентификатор владельца выбирает сервер, а не HTTP-запрос. Этот процесс предназначен для локальной разработки, а публикация Mini App требует T11 и T14.

Vite на `127.0.0.1:5173` использует существующий прокси `/api/`; оба режима обслуживают одни формы. Пользовательский интерфейс не просит токен Telegram или внутренний идентификатор владельца.

## Проверка

Тесты проверяют атомарность и повторяемость импорта, конкурирующие запросы, изоляцию владельцев, точность малых дробей, неверные числа и поля, сохранность подтверждённых планов, архив/восстановление, конфликты редактирования и локальную HTTP-границу. Отдельная миграционная проверка обновляет наполненную схему `0001` до `0002` и возвращает её обратно без изменения рецепта и подтверждённого плана.

Проверка `bash tools/dev/check.sh` прошла: Ruff, mypy (20 файлов), 99 тестов pytest, TypeScript, ESLint, Prettier и сборка Vite. Повторная команда `local_app --init` сохраняет профиль. Импорт модулей, включая локальный процесс, не создаёт БД.

В Chromium проверены оба режима клиента — собранный и Vite-прокси — на 320, 360 и 1280 пикселях без горизонтальной прокрутки. Пройдены добавление, редактирование, явный допуск, отмена, архив, восстановление, просмотр 18 стартовых карточек и запрет импорта до согласования. Ошибка сети и устаревшее сохранение показывают сообщение и сохраняют поля формы. Основной закрытый процесс показывает стартовый экран без запросов к личным маршрутам и без ошибок консоли.
