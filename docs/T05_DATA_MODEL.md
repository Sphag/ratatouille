## Что уже утверждено

- SQLite, SQLAlchemy и Alembic; расчёты отдельными Python-модулями без HTTP и Telegram.
- КБЖУ вводятся вручную на порцию; цели мягкие. Пищевая ценность не вычисляется из ингредиентов.
- План содержит 7 или 28 дней, четыре слота и выбранный режим повторов. Начальный лимит другого режима — три; A/B от него независим.
- Изменения меню остаются черновиком до подтверждения. Отмена сохраняет прежний план; редактирование рецепта не изменяет подтверждённые планы.
- Суммируются совместимые единицы; масса и объём не смешиваются. Отметки относятся к покупкам и партиям готовки.
- Напоминания выключены до настройки; часовой пояс Europe/Moscow. Выполнение уведомлений относится к T12.

## Предлагаемая схема

| Сущность | Основные данные и связь |
|---|---|
| Пользователь | Внутренний идентификатор; необязательный уникальный Telegram ID для будущего связывания в T11 |
| Ингредиент | Владелец, название; явная идентичность продукта для суммирования без догадок по похожим названиям |
| Рецепт | Владелец, текущая версия, признак допуска к подбору и признак архива |
| Версия рецепта | Рецепт, номер версии, название, инструкция, ручные КБЖУ на порцию и выход рецепта в порциях; после сохранения неизменяема |
| Ингредиент версии | Версия рецепта, ингредиент, количество и единица на указанный выход рецепта |
| Дневные цели | Пользователь и ручные цели калорий, белков, жиров, углеводов |
| План | Владелец, начальная дата, длительность 7/28 дней, ссылка на последнюю подтверждённую ревизию |
| Ревизия плана | План, состояние черновик/подтверждена/отменена, режим, лимит, снимок целей и номер для проверки конкурентного изменения |
| Позиция меню | Ревизия, день, слот, ссылка на неизменяемую версию рецепта; одна полная порция на позицию |
| Отметка покупки | Подтверждённая ревизия, неделя, ингредиент, вид единицы и признак «куплено» |
| Отметка готовки | Подтверждённая ревизия, неделя, версия рецепта и признак «приготовлено» |
| Расписание | Пользователь, вид готовка/разморозка, день недели, местное время, признак включения; Europe/Moscow |

Выход рецепта позволяет описать ингредиенты исходной партии при КБЖУ на одну порцию. Для покупки количество ингредиента делится на этот выход и умножается на число запланированных полных порций. Это расчёт требуемого количества продуктов; размеры порций в меню не меняются. Семантика выхода и единиц входит в предлагаемую схему для согласования.

Для рекомендованного личного набора все операции принимают владельца. Связи проверяют принадлежность одного владельца; запрос по чужому идентификатору не возвращает объект. Проверка Telegram `initData` относится к T11: T05 не открывает HTTP-доступ к пользовательским данным через доверенный параметр `user_id`.

Ингредиенты в неизменяемой версии сохраняют снимок названия и единицы. Переименование ингредиента или архивирование карточки не изменяет отображение старого плана. Версии рецептов, используемые планом, не удаляются каскадно. Допуск остаётся явным выбором пользователя и проверяется при будущих предложениях подбора.

Ограничения схемы: уникальная позиция на день и слот; день находится внутри длительности плана; положительный выход и количества; конечные неотрицательные КБЖУ; положительный целочисленный лимит только для режима ограничения. Связи защищаются внешними ключами SQLite, включёнными для каждого подключения.

## Точность и единицы

Предлагается использовать `Decimal` и хранить точные десятичные значения без промежуточного преобразования в `float`. Формат хранения и валидаторы обеспечивают одинаковые результаты после повторного чтения. Значения NaN, Infinity, отрицательные количества, пустые названия и неизвестные единицы отклоняются.

Начальный перечень совместимости: г/кг, мл/л и отдельные штуки. Масса приводится к граммам, объём — к миллилитрам. Один ингредиент в граммах и миллилитрах даёт две строки покупок. Ложки, стаканы, упаковки и другие бытовые меры требуют отдельного явного согласования единиц; плотности и размеры упаковок не угадываются.

Пример проверки: 0,25 кг и 125 г одного ингредиента дают 375 г; 200 мл того же ингредиента остаются отдельной строкой. КБЖУ дня — сумма четырёх фактически заполненных позиций по снимкам рецептов. Недобор и превышение целей отображаются численно и не запрещают сохранение.

## Программные интерфейсы T05

Предлагается реализовать внутренние Python-сервисы и типизированные структуры. HTTP-маршруты для интерфейса добавляются вместе с соответствующими функциями; сейчас HTTP-контракт каркаса остаётся проверкой процесса.

| Операция | Результат и границы |
|---|---|
| Создать/изменить рецепт | Новая версия; старые версии и подтверждённые планы сохраняются |
| Изменить допуск, архивировать/восстановить | Изменить карточку владельца согласно выбранному поведению удаления |
| Сохранить цели и расписание | Валидированные пользовательские настройки; без отправки сообщений |
| Создать черновик | Новый план или копия подтверждённой ревизии со снимком целей |
| Изменить позицию черновика | Новая версия состава черновика; расчёты берутся из фактического состава |
| Рассчитать КБЖУ | Суммы по дням и сравнение с целями |
| Рассчитать покупки и партии | Количества по неделям, ингредиентам и совместимым единицам; число полных порций каждой версии рецепта |
| Подтвердить черновик | Атомарно сохранить ревизию и обновить указатель текущего плана; повторный запрос не создаёт дубликат |
| Отменить черновик | Завершить работу с черновиком без изменения подтверждённого плана |
| Изменить отметку чек-листа | Изменить отметку конкретной подтверждённой ревизии; не переносить автоматически на новое меню |

Ошибки интерфейсов различают некорректный ввод, отсутствие объекта в данных владельца и конфликт версии при одновременном изменении. Подтверждение и изменение черновика используют ожидаемый номер версии, чтобы устаревший клиент не перезаписал новое состояние. Два конкурирующих подтверждения не создают две текущие ревизии.

Подбор меню и проверка его пригодности по режимам реализуются в T08. В T05 хранятся соответствующие параметры и воспроизводимо рассчитывается фактическое меню. Пользовательские интерфейсы рецептов, целей, замен и чек-листов относятся к T06–T11.
