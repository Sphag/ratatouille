<h1 align="center">Ratatouille</h1>

<p align="center">Меню, покупки и готовка на неделю — в Telegram.</p>

Ratatouille помогает заранее составить меню, собрать продукты и спланировать партии готовки. Основной интерфейс — Telegram Mini App на русском языке; бот открывает его и отправляет настроенные напоминания. Первая версия доступна одному владельцу.

## Возможности

- Меню на 7 или 28 дней: ручная сборка и автоматическое предложение без AI, режим A/B либо лимит повторов.
- Библиотека рецептов: 18 стартовых карточек для проверки и импорта, собственные блюда, редактирование, архив и явный допуск к подбору.
- КБЖУ на порцию и дневные цели: ручной ввод, суммы и отклонения; замена с просмотром пересчёта и покупок.
- Недельные покупки и партии готовки: целые порции, совместимые единицы, сохраняемые отметки «куплено» и «приготовлено».
- Независимые напоминания о готовке и разморозке по Москве; до настройки они выключены.
- Личный ICS-файл для ручного импорта готовки и разморозки.

Предложение и замена сохраняют черновик. Подтверждённый план появляется после отдельного подтверждения; отмена копии сохраняет прежний план. Размеры порций автоматически не меняются.

## Состояние

Реализация и локальная приёмка завершены. CI проверяет приложение, Docker build, миграцию, перезапуск и резервирование. Реальные Telegram-клиенты, календарный импорт и выпуск на VPS ещё требуют проверки; публичный работающий сервис пока не объявлен. Матрица проверок и открытые шаги — [приёмка первой версии](docs/T15_ACCEPTANCE.md).

## Локальный запуск

Проверено в WSL/Linux x86_64. Нужны Git, curl и Node.js 24. При необходимости установить Node.js командой `bash tools/mcp/install-node.sh`, затем открыть новый терминал.

Из корня проекта:

```bash
bash tools/dev/setup.sh
npm --prefix frontend run build
bash tools/dev/uv.sh run --locked python -m ratatouille.local_app --init
bash tools/dev/uv.sh run --locked python -m ratatouille.local_app
```

Открыть [http://127.0.0.1:8000](http://127.0.0.1:8000). Установка загружает uv 0.12.23/Python 3.13.16 и использует lockfile. `--init` явно мигрирует БД и создаёт локальный профиль; повторная команда сохраняет его. По умолчанию данные находятся в `data/ratatouille.sqlite3`, другой путь задаёт RATATOUILLE_DB_PATH. Локальный процесс слушает loopback и предназначен для разработки. Токен для него не нужен; напоминания отправляет только отдельный настроенный процесс бота.

В библиотеке проверить стартовые карточки, подтвердить импорт и отдельно допустить выбранные блюда к подбору. В меню задать цели, создать план, просмотреть предложение и подтвердить. Покупки и готовка получают активные отметки после подтверждения. Дни и время задать в разделе «Напоминания».

Для разработки запустить `npm --prefix frontend run dev` в другом терминале. На [http://127.0.0.1:5173](http://127.0.0.1:5173) запросы API идут на локальный Python-процесс.

## Telegram и VPS

Настроить BOT_TOKEN либо BOT_TOKEN_FILE, RATATOUILLE_APP_URL с HTTPS и RATATOUILLE_OWNER_TELEGRAM_ID. `.env` автоматически не читается; переменные передаются процессу явно. Сначала применить миграции, затем запустить сервер и бот отдельно:

```bash
bash tools/dev/uv.sh run --locked python -m ratatouille.database
bash tools/dev/uv.sh run --locked uvicorn ratatouille.server:production_app --factory --host 127.0.0.1 --port 8000
# В другом терминале с теми же настройками:
bash tools/dev/uv.sh run --locked python -m ratatouille.bot
```

Контейнерный запуск, HTTPS, BotFather, файловые секреты, ручной выпуск через CI, резервирование и откат описаны в [инструкции выпуска](docs/T14_RELEASE.md). Сервер и домен пока не выбраны. Процесс `ratatouille.app:app` остаётся стартовым экраном без личных маршрутов; для функций нужен локальный процесс либо защищённая production factory.

## Проверки

```bash
bash tools/dev/check.sh
bash tools/dev/uv.sh run --locked ruff format
npm --prefix frontend run format
```

`/api/health` проверяет процесс; `/api/ready` в защищённом приложении проверяет схему и сборку. Это не подтверждает работу внешнего Telegram.
